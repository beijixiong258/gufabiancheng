## 2. 已确定的AI对话设计

### 2.1 正文和请求

- 允许创建正文为空的草稿。
- 每次AI请求中的编辑器当前正文必须非空且不超过2000个字符，但可以尚未保存。
- 每次对话都把编辑器当前正文放入 `DuihuaDTO.zhengwen` 传给AI。
- 请求中的正文只作为AI上下文，不自动写入数据库。
- `command = 0` 的 `neirong` 必填并保存为人类消息；`command = 1`、`2` 不保存按钮操作。

### 2.2 状态和命令

- 状态枚举已由 `HuihuaZhuangtai` 改名为 `DuihuaZhuangtai`，表示本次AI处理结果，不是持久化的会话状态。
- `CONTINUE` 表示继续交流，`WAIT` 表示AI建议用户选择，`OVER` 表示本次生成完成并返回候选正文。
- `OVER` 不关闭会话，用户之后仍可继续补充新的想法。
- 不把 `CONTINUE/WAIT/OVER` 写入 `Huihua` 或 `Xiaoxi`，不建立强制状态机。
- 三个命令都可以随时调用，不要求先进入 `WAIT`。
- `duihua()` 内部按命令校验结果：命令0可以返回任意合法状态，命令1只接受 `CONTINUE`，命令2只接受 `OVER`。

### 2.3 AI判断

- 已删除 `huiheTongji()`、`huoquTishici()`、`duihuaZhuangtaiJiaoyan()` 和固定5至8轮规则。
- 已删除 `JIXU`、`ZHUIWEN`、`SHENGCHENG` 三个固定回合提示词。
- AI根据题目、题材、标签、编辑器当前正文、会话历史和用户意图决定状态。
- 用户明确要求生成、总结、扩写或润色时应返回 `OVER`。
- 用户明确要求继续讨论或暂不生成时不得返回 `OVER`。
- 用户没有明确倾向时，AI可以自主决定继续、等待或生成。
- 用户没有指定处理方式时，AI可以自行判断总结、扩写或润色；判断不清时可以返回 `WAIT`。
- AI不得编造用户没有提供的重要事实。

### 2.4 候选正文

- `OVER` 的 `quanwen` 只作为普通AI消息保存，不立即更新 `Jilu.zhengwen`。
- 前端根据本次 `DuihuaVO.zhuangtai` 临时标记候选正文，不增加消息类型或状态字段。
- 用户点击使用后，把候选正文放入编辑器；用户可以继续修改或直接确认。
- 用户确认时调用现有 `/jilu/modify` 保存正文，并将记录状态设为 `DRAFT`。
- 不新增后端候选确认接口、候选正文表或文章版本表。
- 后续AI请求继续携带编辑器当前正文，因此AI可以看到尚未保存的修改。
- 刷新后临时候选标记和未保存正文可以丢失；候选文字仍保留在普通消息历史中。

## 5. 有意保留的设计

| 设计 | 保留原因或当前约定 |
| --- | --- |
| 不持久化AI对话状态 | 允许用户中断后带着新想法继续，不用严格状态机限制命令 |
| 不限制固定问答轮数 | 用户意图优先，允许提前生成或继续深入交流 |
| `OVER` 后仍可继续对话 | `OVER` 只表示本次生成完成，不表示会话永久关闭 |
| 候选正文只由前端临时标记 | 第一版保持数据库和后端流程简单 |
| 修改密码使用查询参数 `mima1`、`mima2` | 用户明确决定保留，不改成JSON请求体 |
| 已处理异常仍返回HTTP 200，通过 `Result.code` 表示结果 | 当前前后端联调约定 |
| 认证和管理员授权共用一个 `AuthInterceptor` | 项目规模小，保持简单 |
| 管理员修改接口使用 `GuanliyuanXiugaiDTO` | 空白密码保留原值，非空密码与其他字段执行参数校验 |
| 手机号、身份证号和邮箱允许重复 | 当前业务规则 |
| 不使用Spring Security、JWT或OAuth | 使用Redis Token完成简单认证 |

## 6. 已经修复的重要问题

- 管理员权限判断已经改为使用Spring MVC实际匹配路径。
- AI远程调用不再放入长数据库事务。
- AI失败时不会保存空AI回复或修改正文；已保存的人类消息仍会保留。
- AI返回重复、额外、缺少或类型错误的协议字段时会被拒绝。
- AI对话请求已经统一为 `DuihuaDTO`，不再同时维护重复的消息请求DTO。
- `DuihuaController` 类名、方法名和 `/duihua` 资源路径已经统一。
- 状态枚举已由 `HuihuaZhuangtai` 重命名为 `DuihuaZhuangtai`，源码中全部引用已经同步。
- 固定回合数统计、按回合提示词和状态限制已经删除，普通对话改为按用户意图判断。
- `OVER` 已改为只保存普通AI消息；原 `baocunAIShengchengJieguo()`、更新记录的事务代码和无效依赖已经删除。
- `JiluXiugaiDTO.zhengwen` 和 `DuihuaDTO.zhengwen` 已增加2000字符上限，AI提示词同步限制候选正文长度。
- 会话删除接口已实现为 `DELETE /huihua/delete`，删除会话时由数据库级联删除其全部消息。
- 管理员修改接口已由直接接收 `Yonghu` 改为接收 `GuanliyuanXiugaiDTO`；空白密码不再重置，非空密码和其他字段已增加校验。
