# 实体类与数据库设计

> 技术版本见 [开发总览](./1.开发总览.md)。

## 1. 实体关系

```text
Yonghu 1 —— N Jilu 1 —— N Huihua 1 —— N Xiaoxi
```

- 一个用户可以拥有多条记录。
- 一条记录可以拥有多个会话，每个会话只属于一条记录。
- 一个会话可以拥有多条消息。

初稿、第一次润色和后续修改可以分别创建不同会话，因此记录与会话是明确的一对多关系。

目标数据库结构建立对应外键，并使用级联删除。

## 2. 命名映射

项目在实体类中使用 `@TableName`、`@TableId` 和 `@TableField` 显式声明表名、主键字段和普通字段。`application.yaml` 同时启用了：

```yaml
map-underscore-to-camel-case: true
```

虽然驼峰字段可以自动映射到数据库下划线字段，但当前实体仍采用全量显式注解，映射如下：

| Java字段 | 数据库字段 |
| --- | --- |
| `yonghuId` | `yonghu_id` |
| `jiluId` | `jilu_id` |
| `huihuaId` | `huihua_id` |
| `chuangjianShijian` | `chuangjian_shijian` |
| `xiugaiShijian` | `xiugai_shijian` |
| `chanshengShijian` | `chansheng_shijian` |

## 3. `Yonghu` 用户实体

对应数据库表：`yonghu`。

| Java字段 | Java类型 | 数据库类型 | 说明 |
| --- | --- | --- | --- |
| `id` | `String` | varchar(64) | 当前为32位无连字符UUID |
| `zhanghao` | `String` | varchar(32) | 登录账号，唯一 |
| `mima` | `String` | varchar(255) | 加密后的密码 |
| `dianhua` | `String` | varchar(32) | 手机号，可以为空 |
| `shenfenzheng` | `String` | varchar(32) | 身份证号，可以为空 |
| `youxiang` | `String` | varchar(255) | 邮箱，可以为空 |
| `quanxian` | `Quanxian` | tinyint | 用户权限 |

权限枚举：

```java
USER(0),
ADMIN(1);
```

业务要求：

- `zhanghao` 必须唯一。
- 普通注册的新用户 `quanxian` 固定为 `USER`；管理员新建用户可以指定权限。
- `mima` 保存密码哈希，不保存明文密码。
- 普通用户接口不能返回密码字段。
- `mima` 使用 `@JsonProperty(access = JsonProperty.Access.WRITE_ONLY)`，允许管理员修改请求写入新密码，但任何JSON响应都不序列化该字段。
- 普通用户修改资料时必须提交合法账号；手机号和邮箱只允许修改为合法值，不能清空。
- 管理员可以将手机号、身份证号和邮箱修改为空字符串；传入 `null` 时不更新原值，不把字段恢复为数据库 `NULL`。

## 4. `Jilu` 记录实体

对应数据库表：`jilu`。

| Java字段 | Java类型 | 数据库类型 | 说明 |
| --- | --- | --- | --- |
| `id` | `String` | varchar(64) | 当前为32位无连字符UUID |
| `timu` | `String` | varchar(255) | 题目 |
| `ticai` | `Ticai` | tinyint | 题材 |
| `biaoqian` | `String` | varchar(100) | 标签，可以为空 |
| `zhengwen` | `String` | longtext | 正文，可以为空 |
| `zhuangtai` | `Zhuangtai` | tinyint | 草稿或完成 |
| `yonghuId` | `String` | varchar(64) | 所属用户ID |
| `chuangjianShijian` | `DateTime` | datetime(3) | 创建时间 |
| `xiugaiShijian` | `DateTime` | datetime(3) | 修改时间 |

题材枚举：

```java
QITA(0),
RIJI(1),
WENXUE(2),
XUESHU(3),
HUIYI(4);
```

状态枚举：

```java
DRAFT(0),
FINISH(1);
```

业务要求：

- 新记录默认属于当前登录用户。
- 新记录默认状态为 `DRAFT`。
- 新建记录时只接收题目、题材和可空标签，不接收正文。
- 题目业务长度不超过50位，标签业务长度不超过20位；数据库字段保留 `varchar(255)` 和 `varchar(100)` 的预留空间。
- 新记录正文固定为空，后续通过修改或AI对话写入。
- Controller不能接收前端传入的 `yonghuId` 作为记录归属。
- 查询、修改和删除前都要检查记录是否属于当前用户。
- 已完成记录再次修改正文或由AI生成正文后恢复为 `DRAFT`。

## 5. `Huihua` 会话实体

对应数据库表：`huihua`。

| Java字段 | Java类型 | 数据库类型 | 说明 |
| --- | --- | --- | --- |
| `id` | `String` | varchar(64) | 当前为32位无连字符UUID |
| `jiluId` | `String` | varchar(64) | 所属记录ID |

业务要求：

- 创建会话前检查记录是否存在。
- 普通用户只能为自己的记录创建会话。
- 创建会话本身不自动调用AI。
- 删除记录后会话由数据库级联删除。

## 6. `Xiaoxi` 消息实体

对应数据库表：`xiaoxi`。

| Java字段 | Java类型 | 数据库类型 | 说明 |
| --- | --- | --- | --- |
| `id` | `String` | varchar(64) | 当前为32位无连字符UUID |
| `huihuaId` | `String` | varchar(64) | 所属会话ID |
| `neirong` | `String` | longtext | 消息正文 |
| `laiyuan` | `int` | tinyint | 0为AI，1为用户 |
| `xuhao` | `int` | int | 会话内消息序号 |
| `chanshengShijian` | `DateTime` | datetime(3) | 消息产生时间 |

业务要求：

- 用户发送的消息设置 `laiyuan=1`。
- AI回复设置 `laiyuan=0`。
- 新消息序号等于当前会话最大序号加1。
- 查询消息时按照 `xuhao` 升序排列。
- 同一会话不能出现相同序号。

## 7. 主键设计

四个实体都使用UUID字符串主键。当前通过 `Utils.generateId()` 去除UUID连字符，生成32位字符串，例如：

```text
550e8400e29b41d4a716446655440000
```

Java实体使用 `String`，数据库主键和对应外键统一使用 `VARCHAR(64)`，为以后调整ID格式预留空间。四种实体必须使用相同的生成方法。

## 8. 当前对应情况

当前四个实体均已显式标注表名、主键字段和全部普通字段：

```text
Yonghu  → yonghu
Jilu    → jilu
Huihua  → huihua
Xiaoxi  → xiaoxi
```

四个实体的 `id` 均使用 `@TableId("id")`，其余属性均使用 `@TableField` 对应数据库字段；`Jilu` 已经包含 `biaoqian` 字段。

现有数据库中的ID字段按照当前设计统一为 `VARCHAR(64)`。以下SQL是新建数据库时使用的完整目标结构。

## 9. 完整数据库建表语句

适用数据库版本：MySQL Server 8.0.46。

以下SQL按照外键依赖顺序创建数据库、用户表、记录表、会话表和消息表。SQL不包含删除数据库或删除表的语句。

```sql
CREATE DATABASE IF NOT EXISTS jiluzhushou
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE jiluzhushou;

CREATE TABLE IF NOT EXISTS yonghu
(
    id            VARCHAR(64)     NOT NULL COMMENT '用户ID',
    zhanghao      VARCHAR(32)  NOT NULL COMMENT '登录账号',
    mima          VARCHAR(255) NOT NULL COMMENT '密码哈希',
    dianhua       VARCHAR(32)  NULL COMMENT '手机号',
    shenfenzheng  VARCHAR(32)  NULL COMMENT '大陆身份证号',
    youxiang      VARCHAR(255) NULL COMMENT '邮箱',
    quanxian      TINYINT      NOT NULL DEFAULT 0 COMMENT '权限：0普通用户，1管理员',

    PRIMARY KEY (id),
    UNIQUE KEY uk_yonghu_zhanghao (zhanghao),
    CONSTRAINT ck_yonghu_quanxian
        CHECK (quanxian IN (0, 1))
)
    ENGINE = InnoDB
    DEFAULT CHARACTER SET = utf8mb4
    COLLATE = utf8mb4_unicode_ci
    COMMENT = '用户表';

CREATE TABLE IF NOT EXISTS jilu
(
    id                   VARCHAR(64)     NOT NULL COMMENT '记录ID',
    timu                 VARCHAR(255) NOT NULL COMMENT '题目',
    ticai                TINYINT      NOT NULL DEFAULT 0 COMMENT '题材：0其他，1日记，2文学，3学术，4会议',
    biaoqian             VARCHAR(100) NULL COMMENT '用于分组的标签，可以为空',
    zhengwen             LONGTEXT     NULL COMMENT '当前正文，可以为空',
    zhuangtai            TINYINT      NOT NULL DEFAULT 0 COMMENT '状态：0草稿，1完成',
    yonghu_id            VARCHAR(64)     NOT NULL COMMENT '所属用户ID',
    chuangjian_shijian   DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    xiugai_shijian       DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3)
        ON UPDATE CURRENT_TIMESTAMP(3) COMMENT '修改时间',

    PRIMARY KEY (id),
    KEY idx_jilu_yonghu_zhuangtai (yonghu_id, zhuangtai, xiugai_shijian),
    KEY idx_jilu_yonghu_ticai (yonghu_id, ticai),
    KEY idx_jilu_yonghu_biaoqian (yonghu_id, biaoqian),
    CONSTRAINT fk_jilu_yonghu
        FOREIGN KEY (yonghu_id) REFERENCES yonghu (id)
            ON DELETE CASCADE
            ON UPDATE CASCADE,
    CONSTRAINT ck_jilu_ticai
        CHECK (ticai IN (0, 1, 2, 3, 4)),
    CONSTRAINT ck_jilu_zhuangtai
        CHECK (zhuangtai IN (0, 1))
)
    ENGINE = InnoDB
    DEFAULT CHARACTER SET = utf8mb4
    COLLATE = utf8mb4_unicode_ci
    COMMENT = '记录表';

CREATE TABLE IF NOT EXISTS huihua
(
    id       VARCHAR(64) NOT NULL COMMENT '会话ID',
    jilu_id  VARCHAR(64) NOT NULL COMMENT '所属记录ID',

    PRIMARY KEY (id),
    KEY idx_huihua_jilu_id (jilu_id),
    CONSTRAINT fk_huihua_jilu
        FOREIGN KEY (jilu_id) REFERENCES jilu (id)
            ON DELETE CASCADE
            ON UPDATE CASCADE
)
    ENGINE = InnoDB
    DEFAULT CHARACTER SET = utf8mb4
    COLLATE = utf8mb4_unicode_ci
    COMMENT = '会话表';

CREATE TABLE IF NOT EXISTS xiaoxi
(
    id                    VARCHAR(64)    NOT NULL COMMENT '消息ID',
    huihua_id             VARCHAR(64)    NOT NULL COMMENT '所属会话ID',
    neirong               LONGTEXT    NOT NULL COMMENT '消息内容',
    laiyuan               TINYINT     NOT NULL COMMENT '来源：0 AI，1用户',
    xuhao                 INT         NOT NULL COMMENT '消息在会话中的序号',
    chansheng_shijian     DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '消息产生时间',

    PRIMARY KEY (id),
    UNIQUE KEY uk_xiaoxi_huihua_xuhao (huihua_id, xuhao),
    CONSTRAINT fk_xiaoxi_huihua
        FOREIGN KEY (huihua_id) REFERENCES huihua (id)
            ON DELETE CASCADE
            ON UPDATE CASCADE,
    CONSTRAINT ck_xiaoxi_laiyuan
        CHECK (laiyuan IN (0, 1)),
    CONSTRAINT ck_xiaoxi_xuhao
        CHECK (xuhao >= 0)
)
    ENGINE = InnoDB
    DEFAULT CHARACTER SET = utf8mb4
    COLLATE = utf8mb4_unicode_ci
    COMMENT = '会话消息表';
```
