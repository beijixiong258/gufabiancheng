# 人工智能对话逻辑设计

> 技术版本见 [开发总览](./1.开发总览.md)，接口状态见 [接口设计](./3.接口设计.md)。

## 1. 目标

AI根据记录背景和本会话历史判断信息是否充分：

- 信息不足：只提出一个最有价值的问题。
- 信息充分：生成或润色完整正文。
- 不编造用户未提供的重要事实。

第一版使用Spring AI `ChatClient` 同步取得完整结果，不做流式输出。

## 2. 数据职责

```text
Jilu            保存题目、题材、标签、当前正文和完成状态
Huihua          表示围绕一条记录进行的一次对话
Xiaoxi          保存用户和AI的每条可见消息
AIChatResponse  仅用于后端解析模型JSON
```

一条记录可以创建多个会话。新会话读取记录当前正文作为背景，但只使用本会话的 `Xiaoxi` 作为历史。

前端不需要知道模型内部的 `zhuangtai`，只根据 `Xiaoxi.laiyuan` 判断消息来源：

```text
laiyuan = 1 → 用户消息
laiyuan = 0 → AI回复
```

## 3. 当前入口状态

创建会话本身不调用AI。

`AIChatService.duihua()` 已实现完整业务编排，但当前 `XiaoxiController` 尚未注入并调用它。现有：

```http
POST /xiaoxi/xinjian?huihuaId={huihuaId}
```

仍然只调用 `XiaoxiService.xinjian()` 保存用户消息，不会触发AI。下一步需要把该HTTP入口接入 `AIChatService.duihua()`。

## 4. 当前每轮对话流程

`AIChatService.duihua(yonghuId, huihuaId, neirong)` 当前流程：

```text
检查会话和记录归属
        ↓
保存本轮用户消息
        ↓
查询记录和本会话完整历史
        ↓
组装System/User/Assistant消息
        ↓
事务外调用MiMo
        ↓
解析并校验AIChatResponse
        ↓
状态0：保存AI追问
状态1：短事务保存AI回复并更新正文
        ↓
返回持久化后的AI Xiaoxi
```

用户消息先保存，再查询历史，因此历史中已经包含本轮用户消息；调用模型时不能再额外追加一次 `.user(neirong)`。

## 5. 提示词和消息角色

系统提示词由 `common/ai/Constant.XITONGTISHICI` 保存，当前提供：

- 固定AI行为要求。
- 记录题目 `timu`。
- 题材枚举 `ticai`。
- 标签 `biaoqian`，空值使用缺省说明。
- 当前正文 `zhengwen`，空值使用缺省说明。
- 固定JSON输出协议。

记录背景使用 `SystemMessage`。历史消息按 `xuhao` 升序转换：

```text
laiyuan = 1 → UserMessage
laiyuan = 0 → AssistantMessage
```

当前只把题材枚举值作为背景传入，尚未实现 `QITA`、`RIJI`、`WENXUE`、`XUESHU`、`HUIYI` 各自独立的题材提示规则。

## 6. 模型JSON协议

模型结果解析为：

```java
AIChatResponse
- Integer zhuangtai
- String yindao
- String quanwen
```

需要继续追问时：

```json
{
  "zhuangtai": 0,
  "yindao": "需要询问的问题",
  "quanwen": null
}
```

生成正文时：

```json
{
  "zhuangtai": 1,
  "yindao": null,
  "quanwen": "完整正文"
}
```

`AIChatService.jiaoyan()` 执行业务组合校验：

- `zhuangtai` 不能为空，只能为0或1。
- 状态0要求 `yindao` 非空且 `quanwen` 为空。
- 状态1要求 `yindao` 为空且 `quanwen` 非空。
- 不符合协议时直接返回内部错误，不猜测或修补模型结果。

状态0保存 `yindao` 为AI回复；状态1保存 `quanwen` 为AI回复，并把同一内容写入 `Jilu.zhengwen`。

## 7. 消息序号

当前实现：

```text
下一序号 = 当前会话最大xuhao + 1
没有消息时从1开始
```

数据库通过 `(huihua_id, xuhao)` 唯一约束防止重复。第一版假设同一会话不会并发发送多条消息；以后支持并发时再增加锁、重试或独立序号机制。

## 8. 事务和失败处理

当前事务边界：

```text
单次数据库操作：保存用户消息
事务外：调用MiMo并解析结果
状态0：保存一条AI追问
状态1：XiaoxiServiceImpl.baocunAIHuifu()短事务
       ├─ 保存AI回复
       └─ 更新Jilu正文和DRAFT状态
```

状态1的两项写操作任意一项失败时一起回滚。

AI调用、JSON解析或业务校验失败时：

- 已保存的用户消息保留。
- 不保存空AI回复。
- 不更新正文。
- 返回 `Result.code = 500`。

## 9. 记录状态

- 新建记录为 `DRAFT`。
- AI生成或修改正文后设置为 `DRAFT`。
- 用户主动调用完成接口后改为 `FINISH`。
- 已完成记录再次由AI更新正文后恢复为 `DRAFT`。
