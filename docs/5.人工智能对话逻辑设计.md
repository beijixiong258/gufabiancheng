# 人工智能对话逻辑设计

> 技术版本见 [开发总览](./1.开发总览.md)，接口状态见 [接口设计](./3.接口设计.md)。

## 1. 目标

AI根据记录背景和本会话历史判断信息是否充分：

- 信息不足：只提出一个最有价值的问题。
- 信息充分：生成或润色完整正文。
- 不编造用户未提供的重要事实。

第一版使用Spring AI `ChatClient` 同步取得完整结果，不做流式输出。

## 2. 数据职责

```text
Jilu            保存题目、题材、标签、当前正文和完成状态
Huihua          表示围绕一条记录进行的一次对话
Xiaoxi          保存用户和AI的每条可见消息
AIChatResponse  仅用于后端解析模型JSON
```

一条记录可以创建多个会话。新会话读取记录当前正文作为背景，但只使用本会话的 `Xiaoxi` 作为历史。

前端不直接接收模型内部的 `AIChatResponse`，但会通过 `DuihuaVO.zhuangtai` 得到 `CONTINUE`、`WAIT` 或 `OVER`。消息来源仍根据 `Xiaoxi.laiyuan` 判断：

```text
laiyuan = 1 → 用户消息
laiyuan = 0 → AI回复
```

## 3. 当前入口状态

创建会话本身不调用AI。

`AIChatService` 已由 `DuihuaController` 注入并调用。当前消息入口为：

```http
POST /xiaoxi/fasong?huihuaId={huihuaId}&command={command}
```

当前三个命令均已实现：

```text
command=0 → AIChatService.duihua()，保存人类消息并正常对话
command=1 → AIChatService.jixuYilun()，不保存按钮操作，强制AI继续提问一轮
command=2 → AIChatService.shengchengZhengwen()，不保存按钮操作，强制AI生成正文
```

接口统一返回 `Result<DuihuaVO>`。VO包含 `renleiXiaoxi`、`aiHuida` 和 `zhuangtai`，不包含询问次数。

另外提供：

```http
GET /xiaoxi/lianjie
```

该接口调用 `AIChatService.lianjie()` 测试AI连接；模型返回非空回复时成功，否则返回 `Result.code = 500`。

## 4. 当前每轮对话流程

`AIChatService.duihua(yonghuId, huihuaId, neirong)` 当前流程：

```text
检查会话和记录归属
        ↓
command=0时保存本轮人类消息；command=1或2时不保存按钮操作
        ↓
查询记录和本会话完整历史
        ↓
内部统计已完成问答轮数并选择情境提示词常量
        ↓
组装System/User/Assistant消息
        ↓
事务外调用MiMo
        ↓
解析AIChatResponse并校验字段、轮数和命令状态
        ↓
CONTINUE(1)：保存AI追问
WAIT(2)：保存等待用户选择的AI回复
OVER(0)：短事务保存AI正文并更新记录正文
        ↓
返回包含人类消息、AI回答和状态的DuihuaVO
```

用户消息先保存，再查询历史，因此历史中已经包含本轮用户消息；调用模型时不能再额外追加一次 `.user(neirong)`。

## 5. 提示词和消息角色

系统提示词由 `common/ai/Constant.XITONG_TISHICI` 保存，当前提供：

- 固定AI行为要求。
- 记录题目 `timu`。
- 题材枚举 `ticai`。
- 标签 `biaoqian`，空值使用缺省说明。
- 当前正文 `zhengwen`，空值使用缺省说明。
- 一轮问答的定义和后端统计出的当前轮数。
- 不足5轮、5至7轮、达到8轮三个普通问答情境的独立提示词常量。
- 用户选择继续一轮和用户选择生成正文两个命令情境的独立提示词常量。
- 不足5轮时继续追问；5至7轮且信息充分时进入 `WAIT`；达到8轮时进入 `OVER`。
- `command = 1` 只再提出一个问题，`command = 2` 直接生成正文。
- 固定JSON输出协议。

记录背景使用 `SystemMessage`。历史消息按 `xuhao` 升序转换：

```text
laiyuan = 1 → UserMessage
laiyuan = 0 → AssistantMessage
```

当前只把题材枚举值作为背景传入，尚未实现 `QITA`、`RIJI`、`WENXUE`、`XUESHU`、`HUIYI` 各自独立的题材提示规则。

## 6. 模型JSON协议

模型结果解析为：

```java
AIChatResponse
- Integer zhuangtai
- String yindao
- String quanwen
```

`CONTINUE(1)`，需要继续追问时：

```json
{
  "zhuangtai": 1,
  "yindao": "需要询问的问题",
  "quanwen": null
}
```

`WAIT(2)`，信息已经充分并等待用户选择时：

```json
{
  "zhuangtai": 2,
  "yindao": "目前信息已经比较充分。你想继续补充一个细节，还是现在生成正文？",
  "quanwen": null
}
```

`OVER(0)`，生成正文并结束本次辅助对话时：

```json
{
  "zhuangtai": 0,
  "yindao": null,
  "quanwen": "完整正文"
}
```

`AIChatService.jiaoyan()` 执行业务组合校验：

- `zhuangtai` 不能为空，只能是 `OVER(0)`、`CONTINUE(1)` 或 `WAIT(2)`。
- `OVER(0)` 要求 `yindao` 为空且 `quanwen` 非空。
- `CONTINUE(1)` 和 `WAIT(2)` 要求 `yindao` 非空且 `quanwen` 为空。
- 后端启用JSON重复字段检测，再把模型原始内容解析为 `JsonNode`，要求对象恰好包含 `zhuangtai`、`yindao`、`quanwen` 三个字段，并检查字段类型；重复字段、多字段、少字段或类型错误都会校验失败。
- 不符合协议时直接返回内部错误，不猜测或修补模型结果。

`CONTINUE(1)` 和 `WAIT(2)` 保存 `yindao` 为AI回复；`OVER(0)` 保存 `quanwen` 为AI回复，并把同一内容写入 `Jilu.zhengwen`。

后端内部统计规则为：

```text
已完成问答轮数 = max(人类消息数量 - 1, 0)
```

该轮数只参与提示词选择和状态校验，不写入 `DuihuaVO`。普通对话不足5轮时只接受 `CONTINUE`，5至7轮时接受 `CONTINUE` 或 `WAIT`，达到8轮时只接受 `OVER`。`command = 1` 只接受 `CONTINUE`，`command = 2` 只接受 `OVER`。

## 7. 消息序号

当前实现：

```text
下一序号 = 当前会话最大xuhao + 1
没有消息时从1开始
```

数据库通过 `(huihua_id, xuhao)` 唯一约束防止重复。第一版假设同一会话不会并发发送多条消息；以后支持并发时再增加锁、重试或独立序号机制。

## 8. 事务和失败处理

当前事务边界：

```text
command=0单次数据库操作：保存人类消息
command=1或2：不保存按钮操作
事务外：调用MiMo并解析结果
CONTINUE(1)或WAIT(2)：保存一条AI回复
OVER(0)：XiaoxiServiceImpl.baocunAIShengchengJieguo()短事务
       ├─ 保存AI回复
       └─ 更新Jilu正文和DRAFT状态
```

`OVER(0)` 的两项写操作任意一项失败时一起回滚。

AI调用、JSON解析或业务校验失败时：

- 已保存的用户消息保留。
- 不保存空AI回复。
- 不更新正文。
- 返回 `Result.code = 500`。

## 9. 记录状态

- 新建记录为 `DRAFT`。
- AI生成或修改正文后设置为 `DRAFT`。
- 用户主动调用完成接口后改为 `FINISH`。
- 已完成记录再次由AI更新正文后恢复为 `DRAFT`。

## 10. 当前剩余工作

`DuihuaController` 已使用 `POST /xiaoxi/fasong` 实现三个命令并返回 `Result<DuihuaVO>`，同时提供 `GET /xiaoxi/lianjie` 测试AI连接。

按优先级：

1. 实际运行后验证MiMo是否稳定返回能通过严格字段和情境状态校验的JSON。
2. 如果以后要求刷新页面后恢复 `WAIT`，再把会话状态持久化到 `Huihua`；当前状态只随本次VO返回。
3. 按需要增加不同题材的专用提示规则。

暂不实现流式输出、重新生成、消息撤回、上下文摘要、文章版本历史、文件、图片、音频和知识库。
