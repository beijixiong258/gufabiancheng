# 人工智能对话逻辑设计

> 技术版本见 [开发总览](./1.开发总览.md)。

## 1. 目标

AI不是收到草稿后立即生成最终文章，而是先判断信息是否充分：

- 信息不足：提出一个最有价值的问题。
- 信息充分：根据用户要求生成或润色正文。
- 不编造用户没有提供的重要事实。

第一版使用Spring AI `ChatClient`，同步等待完整文本结果，不做流式输出。

## 2. 数据职责

```text
Jilu    保存题目、题材、标签、当前正文和完成状态
Huihua  表示围绕一条记录进行的一次对话
Xiaoxi  保存用户和AI的每条可见消息
```

一条记录可创建多个会话，每个会话只属于一条记录。初稿、第一次润色和后续修改可以分别创建不同会话。新会话可以读取记录当前正文作为背景，但只把本会话的 `Xiaoxi` 作为对话历史。

## 3. 创建和开始会话

1. 用户先创建 `Jilu`，状态为 `DRAFT`。
2. 用户需要AI帮助时创建 `Huihua`。
3. 创建会话本身不调用AI。
4. 用户通过发送消息接口提交第一条需求。
5. 系统调用AI时传入记录当前信息和本会话历史。

这样可以把普通记录CRUD和外部AI调用分开，便于学习、测试和定位错误。

## 4. 每轮对话流程

```text
用户发送消息
      ↓
检查会话、记录及用户归属
      ↓
计算序号并保存用户消息
      ↓
查询记录和本会话历史消息
      ↓
组织系统提示词、题材提示和上下文
      ↓
ChatClient调用模型
      ↓
解析结构化结果
      ↓
保存AI消息
      ↓
如有正文则更新Jilu
      ↓
返回本轮结果
```

## 5. 提示词组成

### 5.1 固定系统要求

```text
你是AI记录助手。
先判断现有信息是否足以完成用户希望得到的文章或笔记。
信息不足时只问一个最有价值的问题。
信息充分时生成或润色正文。
不得编造时间、人物、数据、结论等重要事实。
必须按指定结构返回结果。
```

### 5.2 记录背景

每轮提供：

- `timu`
- `ticai`
- 可空的 `biaoqian`
- 可空的当前 `zhengwen`

### 5.3 题材要求

- `QITA`：目的、读者、重点、格式和语气。
- `RIJI`：时间、地点、人物、事件、感受和细节，保留用户语气。
- `WENXUE`：主题、场景、情绪、视角和文风。
- `XUESHU`：来源、问题、概念、观点、论据和结论，不虚构资料。
- `HUIYI`：时间、地点、参会人、议题、结论、负责人和截止时间。

### 5.4 历史消息

根据 `huihua_id` 按 `xuhao` 升序传入：

```text
laiyuan = 1 → 用户消息
laiyuan = 0 → AI消息
```

## 6. 结构化AI结果

程序不能仅凭自然语言猜测AI是在“追问”还是“生成正文”。建议要求模型返回固定结构：

```json
{
  "leixing": "ZHUIWEN",
  "huifu": "这件事发生在什么时间和地点？",
  "zhengwen": null
}
```

生成正文时：

```json
{
  "leixing": "ZHENGWEN",
  "huifu": "我已经根据你的补充整理了正文。",
  "zhengwen": "完整正文……"
}
```

Java侧可建立普通结果类，例如：

```text
AiHuifu
- leixing
- huifu
- zhengwen
```

类名和字段名可用英文或拼音，但JSON字段、提示词和Java映射必须一致。

处理规则：

- `ZHUIWEN`：保存 `huifu` 为AI消息，不修改正文。
- `ZHENGWEN`：保存 `huifu` 为AI消息，把非空 `zhengwen` 更新到记录。
- 结构缺失或解析失败：按AI调用失败处理，不能用原始异常文本覆盖正文。

## 7. 消息序号

第一版采用：

```text
下一序号 = 当前会话最大xuhao + 1
没有消息时从0开始
```

一次成功请求通常产生：

```text
用户消息：n
AI消息：n + 1
```

数据库使用 `(huihua_id, xuhao)` 唯一约束。

第一版假设同一用户不会同时向同一会话并发发送多条消息。以后如支持并发，需要增加重试、锁或其他序号生成方案。

## 8. 持久化和失败处理

推荐分为三个阶段：

1. 短事务保存用户消息。
2. 事务外调用AI。
3. 短事务保存AI消息；如返回正文，同时更新 `Jilu.zhengwen` 和修改时间。

AI调用或解析失败时：

- 保留用户消息。
- 不保存空AI消息。
- 不修改正文。
- 返回“AI回复失败，请稍后重试”。

如果用户重试，第一版可以让用户再次发送消息；以后再增加专门的“重新生成”功能。

## 9. 状态规则

- AI生成或修改正文后，记录保持 `DRAFT`。
- 用户调用完成接口后改为 `FINISH`。
- 已完成记录再次修改或继续AI生成正文后恢复为 `DRAFT`。

## 10. 第一版范围

实现：

- 文本消息和完整历史保存。
- 同步调用AI。
- 按题材组织提示词。
- 结构化区分追问与正文。
- AI正文覆盖当前 `zhengwen`。

暂不实现：

- 流式输出、重新生成按钮。
- 消息撤回和编辑。
- 上下文自动摘要。
- 文章版本历史。
- 文件、图片、音频和知识库。
