# 后端公共机制

> 技术版本见 [开发总览](./1.开发总览.md)。

本文件集中说明接口之外的通用后端设计：Redis Token、认证授权拦截器、MVC配置、校验、异常、自动填充和敏感字段保护。

## 1. Redis Token与请求头

第一版使用Redis保存简单Token，不使用Spring Security、JWT和OAuth。

登录请求：

```http
POST /yonghu/denglu
Content-Type: application/json
Accept: application/json

{"zhanghao":"zhangsan","mima":"123456"}
```

登录成功后：

1. 使用项目 `Utils.generateId()` 生成Token。
2. Token为去除UUID连字符后的32位字符串。
3. 在Redis中保存Token对应的用户ID，并设置4天有效期。
4. 将Token字符串放入登录接口的统一响应数据中。

登录管理类内部使用 `StringRedisTemplate`，保存结构：

```text
login:{token} → yonghuId
```

Redis通过Docker数据卷和AOF保存数据。Token是否有效仍以Redis中的Key及其TTL为准。

## 2. Token使用约定

后续需要登录的请求携带：

```http
Authorization: Bearer 550e8400e29b41d4a716446655440000
```

约定：

- Token由登录接口生成，客户端不能自行指定。
- 不接受前端提交的用户ID或 `quanxian` 作为当前身份。
- 拦截器只相信Token对应的服务端用户ID，并从数据库查询最新用户和权限。
- 退出登录时从Redis中删除当前Token。
- Token固定有效期为4天，普通业务请求只验证Token，不自动续期。
- 前端每次启动应用且本地存在Token时调用 `POST /yonghu/shuaxin`。
- Token剩余时间大于5小时时刷新接口返回原Token；剩余时间小于等于5小时时删除旧Token并创建新Token。
- 前端统一保存刷新接口返回的Token；Token已经过期时重新登录。
- JSON请求使用 `Content-Type: application/json`。
- 客户端建议发送 `Accept: application/json`。

## 3. 拦截器与MVC配置

当前使用一个 `AuthInterceptor` 同时完成登录认证和管理员授权。它读取：

```http
Authorization: Bearer <token>
```

拦截器默认保护 `/**`，放行：

```text
POST /yonghu/zhuce
POST /yonghu/denglu
/error
```

以 `/yonghu/admin` 开头的接口额外检查 `ADMIN` 权限。

处理顺序：

```text
AuthInterceptor认证并按路径授权 → Controller → Service归属检查
```

在实现 `WebMvcConfigurer` 的配置类中注册拦截器。拦截器将 `yonghuId`、`token` 和 `quanxian` 放入request属性；Controller使用 `@RequestAttribute` 取得。记录、会话、消息是否属于当前用户仍由Service查询确认。

拦截失败时抛出 `CommonException`，由全局异常处理器返回统一 `Result`。

## 4. 请求参数校验

接口使用独立请求对象，按需要添加：

```java
@NotBlank
@Size
@Email
@Pattern
```

Controller中的JSON参数使用：

```java
@Valid @RequestBody ...
```

类级别可使用 `@Validated` 校验路径参数和查询参数。

第一版重点校验：

- 注册：账号和密码不能为空，长度合理，邮箱格式正确。
- 登录：账号和密码不能为空。
- 记录：题目不能为空，题材不能为空，标签长度不超过数据库限制。
- 消息：内容不能为空。
- 分页：页码和每页条数必须为正数，并限制最大条数。

账号重复、数据归属等需要查数据库的规则属于Service业务校验，不写成注解。

## 5. 全局异常处理

建立业务异常和 `@RestControllerAdvice` 全局处理器，统一处理：

| 异常 | code | 说明 |
| --- | --- | --- |
| 参数校验异常 | 400 | 返回明确的第一个校验信息 |
| 业务异常 | 异常自带 | 账号重复、资源不存在、无权访问等 |
| 未登录 | 401 | 由拦截器返回 |
| 权限不足 | 403 | 由拦截器或业务检查返回 |
| 未知异常 | 500 | 学习联调阶段返回 `e.getMessage()` |

当前全局异常处理器已覆盖：

```text
MethodArgumentNotValidException
MissingServletRequestParameterException
ConstraintViolationException
BindException
```

学习联调阶段未知异常允许返回 `e.getMessage()`，但不主动回显密码、Token或API Key。

## 6. 统一响应

所有Controller返回：

```java
Result<T>
```

状态码：

```text
200 成功
400 参数或业务请求错误
401 未登录
403 没有权限
404 数据不存在
500 服务端或AI调用失败
```

`Result`需要支持：

```java
Result.success()
Result.success(data)
Result.fail(code, message)
```

已被全局异常处理器处理的异常保持HTTP 200；前端统一判断 `Result.code`。

## 7. 创建时间和修改时间自动填充

使用MyBatis-Plus自动填充，不在每个Service重复赋值。

实体字段：

```java
@TableField(fill = FieldFill.INSERT)
private DateTime chuangjianShijian;

@TableField(fill = FieldFill.INSERT_UPDATE)
private DateTime xiugaiShijian;
```

建立实现 `MetaObjectHandler` 的Spring组件：

```text
插入：填充chuangjianShijian和xiugaiShijian
更新：填充xiugaiShijian
```

当前实体使用Hutool `DateTime`，填充值保持同一类型。数据库默认时间可以保留作为兜底，但Java业务写入以MyBatis-Plus填充为准。

`Huihua`当前没有时间字段，不为它额外设计自动填充；以后确有排序需求时再增加。

## 8. 密码和敏感字段

密码处理遵守：

- 注册时使用Hutool 5.8.12提供的BCrypt密码哈希后再保存。
- 登录时使用哈希校验，不能解密比较。
- 日志不打印明文密码和密码哈希。
- 查询接口不返回 `mima`。

推荐双重保护：

1. 用户接口使用不含 `mima` 的响应DTO。
2. `Yonghu.mima`增加 `@JsonIgnore`，防止误序列化。

注册和登录请求DTO可以包含明文密码；实体和任何响应DTO都不能回传密码。管理员查询同样不能返回密码。

`shenfenzheng`属于敏感信息。第一版可以按需求返回给用户本人和管理员，但日志中不要完整输出；以后再按需要做脱敏。

## 9. 事务边界

适合事务：

- 用户注册。
- 记录新增、修改和删除。
- 保存AI消息并更新记录正文。

AI发送流程分段：

```text
事务一：保存用户消息
事务外：调用AI
事务二：保存AI消息，并按结果更新记录正文
```

避免在远程AI调用期间长时间占用数据库事务。

## 10. 配置范围

当前只需要：

- MyBatis-Plus自动填充处理器。
- Spring Data Redis和 `StringRedisTemplate`。
- MVC拦截器注册配置。
- 全局异常处理器。
- 必要的请求DTO和响应VO。

当前已经接入Redis保存登录Token，尚未接入Spring Security、JWT或OAuth。Redis当前不承担通用业务缓存。
